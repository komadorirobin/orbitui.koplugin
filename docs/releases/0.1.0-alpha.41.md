# OrbitUI 0.1.0-alpha.41

Preview release refining the proportions of Bookshelf's native series boxes.

## Changes

- Cover pictures retain their original proportions instead of stretching or
  squashing to fill narrow or wide boxes. They are fitted and centered on the
  front, with the existing cover-coloured board visible around unused space.
- The read-total sits above the picture without cutting into its corner. Long
  counts shrink to fit, and series names stay centered on the entire board.
- Minimum box width increases to 70% of a normal cover. Width still varies with
  the series and respects the native maximum and available shelf space.
- Native perspective, exposed spines, individual completion marks and series
  navigation remain. Ordinary books still face out. No settings, reading data,
  artwork or upstream versions are changed.

Bookshelf remains at `048ab4bad8993ebc713800d884fc485e54753343` (5.5.0 plus
README follow-up), SimpleUI at `36e7430f6379693266d1082ae0b9d88de62cb877`.

## Updating

Use **Uppdatera OrbitUI > Check for updates**, with preview releases enabled.
Install and restart KOReader. Alpha.40 and earlier alpha installations can
update through the unchanged bootstrap/API 1. For manual installation use
`orbitui.koplugin.zip`, not GitHub's source archive.

Keep the previous installation and settings backup. Code rollback returns to
the earlier box appearance without resetting reading data. Earlier migration
caveats still apply: code rollback does not reverse pre-alpha.33 theme-storage
migration or backport newer grouped-order, ledger and module edits.

## Validation Scope

Release gates cover full sequential Lua/LuaJIT integration and component suites,
all 43 translation catalogues, sealed packaging, outgoing-history/artwork checks,
native installer upgrade/rollback from published alpha.40, both CI jobs,
downloaded draft hashes and anonymous public release discovery/download.

Existing SQLite/font dependency skips, absent adjacent Bookends parity checkout
and four external artwork-source audit skips remain. The added tests cover
portrait/square/landscape covers, small and large series, width limits, count
and title placement, high-DPI borders and buffer cleanup after rendering errors.
Physical Bigme rendering still needs testing, especially two-volume/large-series
boxes at cover-size extremes in colour/night mode. Headless tests do not prove
device rendering or performance; no measured speedup is claimed.
