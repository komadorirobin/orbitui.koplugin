# OrbitUI 0.1.0-alpha.55: existing ornament menu fix

This is a small test-alpha hotfix, not the first public beta.

## Fix

Opening **OrbitUI settings > Add-ons > Ornament add-ons** could fail when old,
unmanaged ornament folders already existed. A loop index shadowed the translation
function while building the local-files status label. This happened before any
download, despite the generic message suggesting a connection or storage problem.

The menu now opens normally with these folders present. Regression tests cover
Swedish and English, each legacy Manga folder in both native roots, and opening
the menu from Home without adopting artwork or changing settings.

No artwork, ornament catalog, theme selections, reading data or upstream code is
changed. The six optional packs still use the independent `ornaments-1` release.
Bookshelf 5.5.4 (`982375a7`) and SimpleUI 2.7.5 (`7eb80f9e`) remain the baselines.

## Update

Use **Uppdatera OrbitUI** with preview releases enabled, then restart KOReader.
Alpha.54 can update normally using the unchanged bootstrap API 1. Existing
ornaments do not need to be removed or reinstalled.

Keep a current settings backup. Code rollback does not undo preferences or
separately installed add-ons; never restore old reading progress as part of a UI
rollback. See [OTA recovery](../OTA.md) and [add-on recovery](../ADDONS.md).

After updating, retry opening the ornament menu and continue the
[alpha.54 reader checklist](0.1.0-alpha.54.md#reader-checklist-before-beta).
Fresh setup and the add-on workflow still need physical-device acceptance before
the first beta; automated tests do not replace those checks.
